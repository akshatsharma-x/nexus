### Tutor — `src/app/tutor/page.tsx`, `src/app/api/tutor/route.ts`
- **Fixed a real bug:** the Anthropic client was constructed at module scope, so with no key
  the SDK threw during import and the route 500'd instead of returning the 503 the client's
  fallback expects. Now: key check first, then lazy construction inside the handler.
- Status indicator is real: probes `/api/tutor/status` on mount, holds
  `checking | available | fallback`, and any error/non-ok is treated as fallback. Shows
  `AI TUTOR · AVAILABLE` (model name from the live setting) or `AI TUTOR · FALLBACK MODE`
  ("replies are written locally … not generated"). A successful POST upgrades; a failed POST
  downgrades. The pulsing green dot only exists in available mode.
- Fallback replies carry `source: 'fallback'` (additive field on `AIMessage`) and render
  "Local response · not generated by the model". Fallback prose now reads live readiness,
  gaps and hours instead of frozen "~31% / 23-day streak / 12h" numbers.
- Learner context is derived with `useMemo` from `useOnboarding()` + `useMastery()` +
  `useStoredSettings()` — no duplicated profile state. Sidebar Goal/Readiness/Style rows and
  the suggested prompts follow it instead of literal `'ML Engineer'` / `'Hands-on'`.
- Four settings became functional: `aiModel` → model id (validated through `MODEL_IDS`),
  `contextDepth` → history window (replaces the hardcoded `slice(-10)`), `tutorPersonality`
  → appended tone instruction, `learningAnalogies` → includes/omits the analogy guidance.
- Route also validates message roles, guards an empty `content[0]` (502 → client falls back),
  and never passes an unvalidated model string through.
- Infinite-repeat animations respect `useReducedMotion()`, matching the TopBar idiom.

## Decisions worth knowing
- **Draft-and-commit, not auto-save.** The page already had a Save Changes button; auto-saving
  would have left it decorative.
- **No `SettingsContext`.** Same-tab propagation uses a `nexus:settings-changed` CustomEvent;
  cross-tab uses the native `storage` event.
- **Preference ownership.** Onboarding owns profile facts (roles, skills, hours); Settings owns
  preferences (style, formats, difficulty). Hours prefer onboarding when present so the two
  surfaces can't contradict each other.
- **`export const dynamic` was not used.** It's gone from route-segment-config in Next 16 and
  Route Handlers aren't cached by default here — the build confirms `/api/tutor/status` as `ƒ`.
- **Deliberately not added:** a reduced-motion *setting* (the UI exposes none — the OS
  preference is respected instead), and any Career CTA like "Explore Role" / "View Skill" /
  "Start Learning" — those don't exist on the page and inventing them would add dead buttons.
